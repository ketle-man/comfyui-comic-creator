# 第14章 常见问题

遇到问题时，请先尝试以下三件事。大多数问题都能由此解决。

## 14-1 首先尝试的三件事

| 顺序 | 要做的事 | 容易解决的问题 |
| --- | --- | --- |
| 1 | 在浏览器中刷新 Comic Creator 的标签页（F5 键） | 界面显示异常、按钮没有反应、列表不是最新 |
| 2 | 重启 ComfyUI，重新打开 Comic Creator | 设置（`.env` 等）没有生效、找不到联动节点 |
| 3 | 在“帮助”标签页中搜索出问题的功能名称 | 不明白按钮的含义、本书与当前版本不同 |

> **注意**
> 刷新之前，请先在排版标签页中点击“保存”，保存正在编辑的页面。

## 14-2 按症状处理

### 启动、显示

| 症状 | 原因 | 处理方法 |
| --- | --- | --- |
| 不显示 CC 按钮 | 没有重启 ComfyUI、文件夹放置位置不对、ComfyUI 的界面版本过旧 | 参见第2章 2-7。在地址后加上 `/ccc` 也能打开 |
| 看不到以前制作的作品 | 用了不同的浏览器、不同的地址（`127.0.0.1` 与 `localhost`、端口号）打开 | 用平时的浏览器、地址打开（第1章） |
| 想用中文却显示为日语 | 之前选择过日语，或者浏览器的语言是日语或不支持的语言（第一次打开时会按浏览器的语言显示） | 在“设置”标签页＞“语言”中选择“中文” |
| 部分按钮没有显示为中文 | Image 标签页的工具名、按钮名等，有些部分保持英文；部分界面可能仍显示日文 | 这是正常的。本书也按界面上的显示书写 |

### 作品、页面

| 症状 | 原因 | 处理方法 |
| --- | --- | --- |
| 模板不见了 | 被删除了（一开始自带的“A4竖_3格”“A4横_3格”删除后也不会自动恢复） | 在“页面”标签页＞“模板”＞“创建模板”中制作（第4章） |
| 制作的页面不在作品一览中 | 没有打开作品就制作了页面 | 查看“作品管理”的“组”＞ stock。用“移动”放入作品 |
| 页面大小与作品不一致 | 用“快速”制作了页面 | 使用素材面板“T”中的“作为页面插入”（第4章 4-3） |
| 误删了页面 | — | 从“作品管理”＞“组”＞“回收站”中“恢复”（第5章） |

### 图像、对话气泡、文字

| 症状 | 原因 | 处理方法 |
| --- | --- | --- |
| 图像没有放入想要的分格 | 在分格外松开了鼠标 | 在想放入的分格上松开。放入后也可以用图层面板的“移动”转移 |
| 图像抓不到了 | 图像移到了分格外 | 在图层面板中选中后点击“OC”（第6章） |
| 无法选择、移动图像或对话气泡 | 被锁定（🔒）了 | 在图层面板中改回 🔓 |
| 无法移动对话气泡 | 处于“编辑：OFF”状态 | 把“对话框”的编辑设为“编辑：ON” |
| 台词从对话气泡中溢出 | 对话气泡太小 | 用控制点把对话气泡拉大（第7章） |
| 点击分格也无法放置文字 | 文字模式为关闭 | 打开“文字”的“T”按钮 |
| 在 Image 标签页中文字无法确定 | Enter 是换行 | 用 Ctrl＋Enter（Mac 为 ⌘＋Enter）确定（第9章） |
| 加工后原图不见了 | 用“图像”子标签页加工时，原图会被隐藏 | 用图层面板的 👁 重新显示原图（第6章） |
| 去除背景时出错 | 没有联网／BiRefNet 模型或 Mask Editor One 没有正确安装 | 选择“轻量 (@imgly)”。首次使用需要联网。“BiRefNet”为灰色无法选择时，请检查 Mask Editor One 和模型 |
| 系统字体不显示在列表中 | 使用的不是 Chrome、Edge，或者没有允许访问 | 在 Chrome 或 Edge 中点击“加载系统字体”并允许（第8章） |
| 中文显示为方框或乱码 | 所选字体不包含中文字符 | 选择支持中文的字体（第7章、第8章） |

### 导出

| 症状 | 原因 | 处理方法 |
| --- | --- | --- |
| 只导出了部分页面 | 修改了“输出页面”的范围 | 确认范围，设为“1 〜 最后一页”（第4章 4-7） |
| 导出了其他作品的页面 | “解除”了列表的筛选 | 在“作品管理”中选择作品，从“输出”按钮打开 |
| 导出时文字的字体变了 | 网络字体尚未加载（离线时等） | 在联网状态下先显示一次页面，然后再导出 |
| 草稿没有被导出 | 草稿图层按设计不会被导出 | 要导出的内容请放在分格或覆盖层中 |

### AI、联动

| 症状 | 原因 | 处理方法 |
| --- | --- | --- |
| Nanobanana 显示未设置 API 密钥 | 没有 `.env`、写法不对、没有重启 ComfyUI | 参见第10章 10-3。`.env` 放在 Comic Creator 文件夹的根目录 |
| Nanobanana 中无法插入第2张以后的图像 | 没有在缩略图中选择（初始选中第1张） | 点击结果下方的缩略图选中后，再点击“插入到分格”。图像也会保留在 `ComfyUI/output/cc_nanobanana/` 中 |
| Nanobanana（原生）显示“未设置COMFY_API_KEY” | `.env` 中没有 `COMFY_API_KEY`，或者没有重启 ComfyUI | 在 `.env` 中写入 `COMFY_API_KEY=密钥` 并重启。不使用的话，把设置标签页的“生成方式”改回 Gemini API（第10章） |
| 原生方式下无法使用 Nano Banana Pro，Lite 无法选择 2K、4K | 原生节点方式的限制（不支持 Pro，Lite 仅支持 1K） | 把设置标签页的“生成方式”改为 Gemini API |
| MOSS-Image 显示“ComfyUI 不支持” | ComfyUI 是不支持 MOSS-Image 的旧版本 | 更新 ComfyUI 并重启 |
| MOSS-Image 显示“未找到模型” | 扩散模型、文本编码器、VAE 不在指定的文件夹中 | 放到第10章 10-6 表中的位置，然后点击“重新加载模型列表” |
| MOSS-Image 中空文字框的位置什么都没画 | 按设计，文字为空的框不会发送 | 在框中输入文字 |
| MOSS-Image 在图像中画出了文字或框 | 提示词中含有“封面”“杂志”等词，或者有文字框 | 勾选“禁用文字生成”，或从提示词中去掉这些词（第10章 10-6） |
| Nanobanana+ 的“本地”显示“未注册本地工作流” | 没有注册工作流 | 从“⚙”注册 Workflow Studio 的工作流（第10章 10-7） |
| Nanobanana+ 的“本地”中只用了部分图像 | 工作流的图像输入数量不够（Qwen Image 2.1 以外最多到固定数量） | 把图像张数控制在“(张数/上限)”显示的范围内 |
| OCR 标签页的状态显示“无法连接 Ollama”“未找到 OCR 模型” | Ollama 没有运行，或者没有安装模型 | 启动 Ollama，用 `ollama pull` 安装模型后点击“重新加载模型列表”（第10章 10-8） |
| OCR 读不出竖排文字，结果为空或同一文字重复 | OCR 模型各有擅长与不擅长的领域 | 使用“整图识读（Chat TE）”，或使用“裁剪文字框并用另一个模型重新识别”（第10章 10-8）。重复时会自动以灰度重试 |
| OCR 的“整图识读”失败 | ComfyUI 中没有安装 Chat TE，或者显存不足 | 安装 Chat TE 并重启 ComfyUI。开启“显存调整（Ollama）” |
| 使用整图识读（Chat TE）或 MOSS-Image 后，生成全部失败／显示无法连接 ComfyUI | 整图识读的模型和图像生成的模型同时载入 GPU 内存，ComfyUI 报错停止（在 v1.68.1 以前容易发生） | 重启 ComfyUI。更新到 v1.69.0 以上后，模型会自动切换（第10章 10-8）。旧版本请在切换前点击 ComfyUI 的“Unload Models” |
| 在 MOSS-Image 或 OCR 中，本想移动框却画出了新框 | 在“绘制”状态下拖动了 | 切换为“选择”后再移动。画出的框用 Delete 键删除，删多了用 Ctrl＋Z 恢复（第10章） |
| “workflow studio”标签页中显示“未找到 Workflow Studio” | 没有安装 ComfyUI-Workflow-Studio | 安装后重启 ComfyUI（不使用的话保持原样即可） |
| Generate 后原图仍然保留 | 生成的图像会叠加添加在上方 | 在图层面板中删除不需要的原图 |
| Auto 中显示“Failed to fetch” | 本地 LLM 的 URL 与打开的地址不一致 | 统一 URL 的主机名（如果是 `127.0.0.1`，就用 `http://127.0.0.1:11434`） |
| 决策模型显示为未设置 | 用了与 Workflow Studio 不同的地址打开 | 用与 Workflow Studio 相同的地址（包括端口号）打开 |
| 3D 姿势、3D 文字出错 | 没有安装 comfyui-vrm-pose-editor，或文件夹名不对 | 把文件夹名设为 `comfyui-vrm-pose-editor` 后安装（第2章） |
| 打开 PixiJS FX 时出错 | 没有安装 comfyUI-particle-pixijs | 安装后重启 ComfyUI |
| 生成图像时 GPU 内存不足 | Ollama 的模型占用了显存 | “设置”＞“显存调整（Ollama）”（第13章） |
| G'MIC 打不开 | 可执行文件的位置不对 | 在“设置”＞“G'MIC 设置”中确认是否有红色警告 |

> **本章小结**
> - 遇到问题时，依次尝试“刷新”“重启 ComfyUI”“在帮助标签页中搜索”
> - 看不到作品时，请确认浏览器和地址
> - 导出时务必确认“输出页面”的范围
> - 联动功能出错时，请确认是否安装了所需的自定义节点，以及是否重启了 ComfyUI
