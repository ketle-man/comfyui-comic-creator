# 第10章 AIで絵を作る：Nanobanana+・Workflow Studio・MOSS-Image・OCR

第10章から第12章では、サンプル作品を1つ作りながら、AI と連携する機能を順に使っていきます。

## 10-1 この章から作るサンプル作品

サンプル作品は、次のような2ページの短いマンガです。

| 項目 | 内容 |
| --- | --- |
| 作品名 | ねこカフェの朝 |
| サイズ | A4 縦 |
| ページ数 | 2ページ |
| 登場人物 | 猫の店員「ミケ」と、はじめて来たお客さん |
| あらすじ | 開店前のカフェで、ミケが朝の準備をしている。そこへお客さんが早く来てしまい……。 |

各章で行うことは次のとおりです。

| 章 | やること |
| --- | --- |
| 第10章（この章） | 背景とキャラクターの絵を AI で作り、コマに入れる |
| 第11章 | 脚本を書き、AI でコマ割りとセリフを作る |
| 第12章 | 3D ポーズや効果で仕上げる |

まず第4章の手順で、作品「ねこカフェの朝」（A4 縦）を作り、3コマのテンプレートで2ページ分を挿入しておきましょう。

## 10-2 2つの方法の違い

Comic Creator で AI の絵を作る方法は2つあります。

| | Nanobanana | Workflow Studio 連携 |
| --- | --- | --- |
| 生成する場所 | Google のサーバー（Gemini API） | 自分のパソコンの ComfyUI |
| 必要なもの | Gemini の API キー | ComfyUI-Workflow-Studio と、画像生成のモデル・ワークフロー |
| GPU | 不要 | 必要 |
| 料金 | 使い方によっては Google の料金がかかる | かからない（電気代のみ） |
| 向いていること | 手軽に試す、参照画像でキャラクターをそろえる | 好きなモデルで作る、コマを見ながら描き直す、部分修正 |

どちらか一方だけでもかまいません。この章では両方を順に説明します。

> **ポイント**
> 「Nanobanana+」タブには、上の「ローカル」モードもあります。Workflow Studio に保存したワークフロー（Flux.3 Image Klein、Qwen Image 2.1 など）を、Nanobanana と同じ画面で使えます（10-7）。

> **ポイント**
> このほかに、ComfyUI 本体が対応した画像生成モデルを使う「MOSS-Image」タブがあります（10-6）。こちらも自分のパソコンで動き、物体・キャラクター・セリフの位置を指定して、ページ全体を一度に生成できるのが特徴です。

## 10-3 Nanobanana の準備

Nanobanana は、Google の Gemini API で画像を作る機能です。使うには API キーが必要です。タブの名前は「Nanobanana+」です（ローカルのワークフローでも使えるようになったため。10-7）。本書では、Gemini API で作る使い方を「Nanobanana」モードと呼びます。

1. Google AI Studio などで、Gemini の API キーを取得します（取得方法は本書では扱いません）。
2. Comic Creator のフォルダに、`.env` という名前のファイルを作ります。

   ```
   ComfyUI/custom_nodes/comfyui-comic-creator/.env
   ```

3. `.env` に次の1行を書いて保存します（`あなたのAPIキー` の部分を、取得したキーに置き換えます）。

   ```
   NANOBANANA_API_KEY=あなたのAPIキー
   ```

4. ComfyUI を再起動します。

「Nanobanana+」タブを開き、上の「Nanobanana」を選んだ状態で、API キーが設定されていないという表示が出なければ準備完了です。

> **注意**
> API キーは、他人に見せてはいけない大切な情報です。`.env` ファイルを人に渡したり、インターネットに公開したりしないでください。

> **注意**
> `.env` は ComfyUI の起動時に読み込まれます。キーを書いたり変えたりしたら、必ず ComfyUI を再起動してください。

### 生成方式を切り替える：ComfyUI ネイティブノード

Nanobanana には、自分の Gemini API キーで生成する方法のほかに、ComfyUI 本体の Nano Banana ノードを使う方法があります。「設定」タブの「Nanobanana 設定」にある「生成方式」で切り替えます。

| 生成方式 | 内容 | 必要なもの |
| --- | --- | --- |
| Gemini API（自分のAPIキー）（既定） | Google の Gemini API で直接生成する。履歴は `history.jsonl` に記録される | `.env` の `NANOBANANA_API_KEY` |
| ComfyUIネイティブノード（Comfyクレジット） | ComfyUI 本体の Nano Banana ノードで生成する。Comfy クレジットを消費する | `.env` の `COMFY_API_KEY`（platform.comfy.org で発行） |

この設定は、Nanobanana+ タブのほか、スクリプトタブの半自動マンガと、Auto タブ（画像生成エンジンが Gemini のとき）にも共通で効きます。Nanobanana+ タブの基本設定にも同じ選択欄があり、設定タブと連動します。

| 違い | 内容 |
| --- | --- |
| 履歴 | ネイティブノードでは、生成条件が出力 PNG に埋め込まれるため、履歴の自動記録と「履歴に記録」ボタンは出ない |
| 保存先 | Nanobanana+ タブの画像は `ComfyUI/output/cc_nanobanana_native/` に保存される |
| 使えないモデル | Nano Banana Pro（gemini-3-pro-image）は未対応。Nano Banana 2 Lite は 1K のみ |

> **注意**
> `COMFY_API_KEY` も `.env` に書いて ComfyUI を再起動するまで反映されません。キーがないと、接続状態の表示が「COMFY_API_KEY未設定」になります。

## 10-4 Nanobanana で背景とキャラクターを作る

### 背景を作る

画面は左右に分かれています。左がプロンプトと基本設定、右が参照画像（Image-to-Image）です。上には、タブの名前の下に「Nanobanana／ローカル」の切り替えがあり、サブタブは「生成設定」と「Nanobanana履歴」の2つです。

1. 「Nanobanana+」タブを開き、上の「Nanobanana」を選びます。
2. Positive Prompt（作りたい絵の説明）を入力します。英語でも日本語でもかまいません。
   ```
   落ち着いた雰囲気のカフェの店内、朝の光、木のカウンター、マンガの背景、モノクロ
   ```
3. 「モデル」と「解像度」（縦横の比率）を選びます。コマが横長なら 3:2 や 16:9 を選びます。
4. 「画像を生成」を押します。しばらくすると結果が表示されます。

| 項目 | 内容 |
| --- | --- |
| モデル | gemini-3.1-flash-lite-image ／ gemini-3.1-flash-image ／ gemini-3-pro-image ／ gemini-nano-banana-2.1 |
| 解像度 | 縦横の比率（1:1、2:3、3:2、9:16、16:9） |
| 出力解像度 | 1K（既定）／2K／4K。対応していないモデルでは 1K のままのことがある |
| 生成枚数 | 一度に作る枚数 |
| Negative Prompt | 入れたくないものの説明 |

### コマに入れる

1. 「レイアウト」タブで、背景を入れたいコマ（例：1ページ目の1コマ目）をクリックして選びます。
2. 「Nanobanana+」タブに戻り、結果の下の「コマに挿入」を押します。

> **注意**
> 「生成枚数」を2枚以上にすると、結果の下にサムネイルが並びます。サムネイルをクリックして選んだ画像が、プレビューに表示され、「コマに挿入」で入ります（最初は1枚目が選ばれています）。生成した画像は、すべて次の保存先フォルダにも残ります。

生成した画像は、ComfyUI の次のフォルダに自動で保存されます。

```
ComfyUI/output/cc_nanobanana/
```

### 参照画像でキャラクターをそろえる（I2I）

マンガでは、同じキャラクターを何コマにも描く必要があります。画面右の「Image-to-Image」に参照画像を入れると、参照画像を見せながら生成できるので、キャラクターの見た目をそろえやすくなります。

1. まず、ミケの全身の絵を1枚作ります。
   ```
   三毛猫の女の子のキャラクター、カフェの店員のエプロン、全身、白背景、マンガ風
   ```
2. 右の「Image-to-Image」で、「画像追加」を押して今作ったミケの画像を追加します（最大14枚。パソコンの画像をここへドラッグ＆ドロップしても追加できます）。
3. 左の Positive Prompt に場面を書いて生成します。
   ```
   参照画像のキャラクターが、カウンターでコーヒーをいれている。マンガのコマ、モノクロ
   ```

> **ポイント**
> Gemini の画像生成には、「どれくらい元の画像から変えるか」を数値で決める設定がありません。変化の強さは、プロンプトの書き方で調整します（「ポーズだけ変えて」「服はそのまま」など）。

### 履歴を残す

「生成時に自動で履歴に記録」をオンにすると、生成した日時・モデル・プロンプトなどが記録されます。オフでも、結果の「履歴に記録」で、気に入ったものだけ記録できます。記録は「履歴」サブタブで見られます。

> **ポイント**
> 履歴は `ComfyUI/output/cc_nanobanana/history.jsonl` に1行1件で追記されます。アプリの中では消せないので、消したいときはテキストエディタでこのファイルを開いて、その行を削除します。

## 10-5 Workflow Studio と連携する

ComfyUI-Workflow-Studio（以下、Workflow Studio）を入れていると、自分の ComfyUI で画像を作れます。Comic Creator からは、ページやコマを見ながら生成を指示できます。

> **注意**
> Workflow Studio の使い方、モデルやワークフローの用意は、本書では扱いません。Workflow Studio 側で、画像を作れる状態にしておいてください。

### レイアウトタブの「Generate」

レイアウトタブの操作バーの「Generate」を押すと、生成の画面が開きます。

| 項目 | 内容 |
| --- | --- |
| 対象 | 選択画像／ページ全体／選択タブ（下の表） |
| プロンプトタブ | 「全体」と、「コマ1」「コマ2」…のタブ。コマごとに別のプロンプトを書ける |
| T2I | オンにすると、今の画像を使わず、文章だけから新しく作る。オフ（既定）は今の画像を元に作り直す（I2I） |
| Denoise | I2I で、元の画像からどれくらい変えるか（大きいほど大きく変わる） |
| batch | 「ページ全体」のときだけ表示。オンにすると、コマごとに順番に作る |
| Run | 生成を始める |

| 対象 | 使うプロンプト | 結果が入る場所 |
| --- | --- | --- |
| 選択画像 | 「全体」タブ | 新しい画像として追加 |
| ページ全体（batch オフ） | 「全体」タブ | オーバーレイに、ページいっぱいの大きさで追加（ラフの確認向け） |
| ページ全体（batch オン） | 「全体」＋各コマのタブ | 各コマに、コマいっぱいの大きさで追加 |
| 選択タブ | 選んでいるコマのタブだけ | そのコマに、コマいっぱいの大きさで追加 |

> **注意**
> どの対象でも、元の画像は消えずに残り、生成した画像がその上に重なります。不要になった元の画像は、レイヤーパネルで削除してください。

### サンプルで使ってみる：コマごとに描き直す

1ページ目の3コマを、コマごとのプロンプトで作ってみます。

1. 「Generate」を開き、「対象」で「ページ全体」を選び、「batch」と「T2I」をオンにします。
2. 「全体」タブに、作品全体の雰囲気を書きます。
   ```
   manga style, monochrome, cafe interior, morning
   ```
3. 「コマ1」「コマ2」「コマ3」のタブに、それぞれの場面を書きます。
   ```
   コマ1：wide shot of an empty cafe before opening
   コマ2：a calico cat girl in an apron wiping the counter
   コマ3：the door opens, surprised cat girl
   ```
4. 「Run」を押します。コマ1から順に生成され、コマに入ります。

うまくいかないコマだけ作り直すときは、「対象」を「選択タブ」にして、そのコマのタブを選んで「Run」を押します。

> **ポイント**
> 第11章の「Auto」で脚本を作っておくと、「Autoから取得」で、脚本の各コマの「背景描写・演技指示」をコマのタブに自動で入れられます。

> **ポイント**
> 画面下の「ワークフロー設定」で、I2I 用・T2I 用のワークフローのファイル名を指定しておくと、生成のたびにそのワークフローが自動で読み込まれます。指定しないときは、Workflow Studio でいま開いているワークフローが使われます。

### Image タブで部分修正する

Image タブでは、Workflow Studio を使って、画像の一部だけを AI で描き直せます（第9章）。

| 機能 | 場所 | 内容 |
| --- | --- | --- |
| I2I | Select ツールの右のパネル | 全体（All）または選んだレイヤー（Layer）を元に作り直す。結果は新しいレイヤーになる |
| Inpaint | Mask ツール | マスクで白く塗った範囲だけを描き直す |
| Outpaint | Mask ツール | 上下左右に余白を足して、画像の外側を描き足す |

例：ミケの手の形がおかしいときは、Mask ツールで手のあたりを塗り、「Inpaint」で「cat paw holding a coffee cup」などと入力して「Run」を押します。

### そのほかの連携

| 機能 | 内容 |
| --- | --- |
| 「workflow studio」タブ | Workflow Studio のギャラリーを表示する。上の「ws再読込」で再読み込み、「ws新しいタブで開く」で別タブに開く |
| Image タブの「wsI2I」 | 編集中の画像を Workflow Studio の I2I の入力に送る。結果は Workflow Studio のギャラリーで「Send CC（Image）」を押すと、Image タブに戻る（作業中のレイヤーがあれば新しいレイヤー、なければ新しいキャンバス）。Workflow Studio v0.8.11 以降が必要 |

### Ollama と同時に使うとき

ローカルの AI（Ollama）で脚本を作りながら画像も生成すると、GPU のメモリ（VRAM）が足りなくなることがあります。「設定」タブの「VRAM調整（Ollama）」で、画像を生成する前に Ollama のモデルを片付けるように設定できます（第13章）。

## 10-6 MOSS-Image タブでページ全体を作る

「MOSS-Image」タブは、ComfyUI 本体が対応した画像生成モデル「MOSS-Image」を使って、自分のパソコンで画像を作る機能です。Comfy クレジットも API キーも要りません。

最大の特徴は「レイアウトエディタ」です。画像の中に「物体」「キャラ」「文字」の枠（四角形）を置いて、どこに何を描くかを指定できます。日本語のセリフや擬音の位置まで決められるので、ページ全体（コマ割りとセリフ）を一度に生成する使い方ができます。

### 必要なもの

- MOSS-Image に対応した ComfyUI（古い ComfyUI では「ComfyUIが未対応です」と表示されます。ComfyUI を更新してください）
- ComfyUI にモデルファイルを入れること

| 種類 | 置く場所 | ファイルの例 |
| --- | --- | --- |
| 拡散モデル | `ComfyUI/models/diffusion_models/` | `moss_image_sft_int8_convrot.safetensors` など |
| テキストエンコーダ | `ComfyUI/models/text_encoders/` | `qwen3.5_9b_w4a8_gptq.safetensors` |
| VAE | `ComfyUI/models/vae/` | `flux2-vae.safetensors` |
| LoRA（なくてもよい） | `ComfyUI/models/loras/` | 高速生成用の DMD 8step など |

タブの上に、状態が「MOSS-Image: 利用可能」「モデルが見つかりません」「ComfyUIが未対応です」「ComfyUIに接続できません」のどれかで表示されます。モデルを入れた直後は「モデル一覧を再読込」を押してください。

> **ポイント**
> モデルのファイル名や入手先は、モデルの配布ページで確認してください。本書では扱いません。MOSS-Image は英語と中国語が公式の対応言語で、日本語は公式対応の外です。文字の描画は、枠の中の文字が正確に出るとは限りません。生成後に確認してください。

### 画面の構成

| 場所 | 内容 |
| --- | --- |
| 左 | レイアウトエディタ。枠を描いて、物体・キャラ・文字を配置する |
| 中央 | 「プロンプト」「JSON」「モデル・サンプラー」の3つのタブ |
| 右 | 画像を生成するボタン、シード、結果、ページへ配置するボタン |

### はじめての1枚：ページ全体を生成する

1. 「レイアウト」タブで、セリフまで入れたページを開いておきます。
2. 「MOSS-Image」タブを開き、中央の「プロンプト」タブの「生成対象」で、モードを「1頁まるごと」にします。
3. 左の「現在のページのコマを取り込む」を押します。ページのコマが「物体」の枠として入り、キャンバスはページの縦横比（約 2MP）に合わせて変わります。
4. 「フキダシ・セリフを取り込む」を押します。セリフの入ったフキダシが、「文字」の枠として入ります。
5. 「プロンプト」に、画像全体の説明を書きます（英語がおすすめです）。
6. 右の「画像を生成」を押します。
7. 結果が出たら、「レイアウト オーバーレイ」を押します。ページ全面のオーバーレイに画像が入ります。気になるところは、「Imageタブで開く」で Image タブに送って直せます。

> **ヒント**
> 画像に文字が描かれるのを避けたいときは、「画像を生成」の下の「テキストを無効で生成」にチェックを入れます。レイアウトの文字枠を消さずに、生成のときだけ送らない設定です。全体のプロンプトに「表紙」「雑誌」「タイポグラフィ」のような語が入っていると、文字が描かれやすくなります。

> **ヒント**
> 速さを優先するなら、「モデル・サンプラー」タブのプリセットで「高速 DMD 8step」を選びます（LoRA が必要です）。標準は 50 ステップで時間がかかります。

### 生成モード

| モード | 動き |
| --- | --- |
| 1頁まるごと | キャンバス全体を1枚で生成し、結果をページ全面に配置する（全コマと文字をレイアウトで指定する） |
| コマ単位 | 選んだコマごとに、コマの縦横比に合わせて生成し、そのコマに配置する。コマごとの内容（英語がおすすめ）を入力できる |
| 自由サイズ | 生成だけをして、配置はしない |

### レイアウトエディタの使い方

上の「描画種別」で、物体（緑）・キャラ（ピンク）・文字（水色）・コマ（黄色）のどれを描くか選び、キャンバスをドラッグして枠を描きます。

| 操作 | 動き |
| --- | --- |
| 空いている所をドラッグ | 選んだ種別で新しい枠を描く |
| 枠の縁・番号・選択中の枠の内側をドラッグ | 枠を移動する |
| 枠の角をドラッグ | 枠を拡大・縮小する |
| Shift キーを押しながら枠をクリック（ドラッグしない） | 選んでいる枠に、その枠を追加（または外す）。選んだ枠はまとめて移動できる |
| 選んでいない枠の内側をドラッグ | その上に新しい枠を描く（コマの上にセリフの枠を置ける） |
| 選んでいない枠の内側をクリック | 枠を選ぶ |
| Shift キーを押しながらドラッグ | いつでも新しい枠を描く |
| Delete キー | 選んでいる枠を削除する |

「最前面」「前面へ」「背面へ」「最背面」で重なりの順番を変えます（「最前面」「最背面」は一番上・一番下へ一気に動かします）。描画種別の左の「新規作成」を押すと、すべての枠を消して白紙に戻します。枠を選ぶと、中央に「選択中の要素」が出て、種別・説明（caption、英語がおすすめ）などを直せます。

### 文字の枠

- 「文字」の枠は、描いた直後に枠の中へ直接文字を入力できます。確定は Esc／Ctrl＋Enter／枠の外のクリックです（Enter は改行）。
- 文字の枠をすばやく2回押すと、入力し直せます。
- フォントサイズ（画像上の px）を決められます。入力した文字の大きさに枠が合います（目安の計算です）。
- 「文字」の右隣の「横書き」「縦書き」は、これから描く枠の書字方向です。描いたあとに変えるときは、「選択中の要素」の「書字方向」で変えます。

> **ポイント**
> MOSS-Image の仕組みには縦書きの指定がないので、縦書きの枠には、縦書きを指示する英文が説明（caption）の末尾に自動で付きます。JSON タブで確認できます。

> **注意**
> 文字が空の「文字」枠は、生成のときには送られません（送ると、その場所に罫線入りの紙のようなものが描かれることがあるため）。画面では点線で薄く表示されます。

### ページから取り込む

| ボタン・項目 | 動き |
| --- | --- |
| 現在のページのコマを取り込む | 開いているページのコマ枠を、枠として取り込む。「コマを panel ラベルで取り込む」にチェックを入れると「コマ」の種別（黄色）になり、外すと「物体」になる |
| フキダシ・セリフを取り込む | セリフ入りのフキダシを、フキダシの輪郭の大きさの「文字」枠として取り込む。フキダシの形（ふつう・思考・叫びなど）、縦書き、文字の大きさも引き継ぐ |
| 吹き出しなしの文字も取り込む（既定でオン） | テキストツールで置いた、フキダシに入っていない文字も「文字」枠にする |

- 取り込んだ枠は、読み順（上から下、同じ段は右から左）に並びます。
- 取り込み直すと、前に取り込んだ枠だけが入れ替わり、自分で足した枠は残ります。
- 「取り込み全クリア」を押すと、取り込んだコマ・フキダシ・セリフの枠だけが消え、自分で描いた枠は残ります。古いバージョンで取り込んだコマの枠は消えないので、そのときは「新規作成」を使います。
- キャンバスの縦横比がページと違うときは、ページに合わせて既存の枠も拡縮するかを確認されます。
- 取り込んだ枠は、文字を直しても枠が縮みません（「枠を文字の大きさに合わせる」がオフ）。
- 回転した文字は、回転後の外側の四角形で取り込まれます。MOSS-Image の枠は回転を表せません。
- フキダシに入っていない文字の説明（caption）は、すべて「ナレーション」になります。以前は6文字以下を擬音としていましたが、名前などが擬音になってしまうため廃止しました。擬音として描かせたいときは、「選択中の要素」の説明（caption）に、擬音であることを英語で書き足します。

### シードの動作

右の「シード」で、毎回の絵のばらつき方を選びます。

| 動作 | 内容 |
| --- | --- |
| ランダム（既定） | 毎回違うシードで生成する。入力欄の値は使わない |
| 固定 | 入力欄の値で生成する。同じ設定なら似た結果になる |
| 生成ごとに+1 | 入力欄の値から始め、生成するたびに1つずつ増やす |

ランダムで使われたシードは「直前のシード」に表示されます。気に入った絵が出たら、その横の「このシードを固定」を押すと固定に切り替わります。

### そのほかの設定

- 「プロンプトを拡張する」にチェックを入れると、短い指示を、ComfyUI のテキストエンコーダ（LLM）が詳しい英語の説明に書き換えてから生成します。短い一言だけで試したいときに向いています。レイアウトの枠を使う「1頁まるごと」では効きません（枠の指定が壊れるため）。書き換えた文章は画面には出ません。
- 中央の「JSON」タブには、実際に送られる内容（レイアウト JSON）が出ます。「JSONを直接編集して送信する」にチェックすると、手で書いた JSON をそのまま送れます（レイアウトは無視されます）。
- 「モデル・サンプラー」タブでは、プリセット（標準・軽量・高速 DMD 8step・高速 Turbo 4step）と、モデル・LoRA・ステップ数・CFG などを選びます。
- 生成した画像は、ComfyUI の `output/cc_moss/` に保存されます。
- 設定とレイアウトはブラウザに保存され、開き直しても元に戻ります。
- 「設定」タブの「VRAM調整（Ollama）」（第13章）は、MOSS-Image の生成前にも働きます。

## 10-7 Nanobanana+ のローカルモード

「Nanobanana+」タブの上にある「Nanobanana／ローカル」の切り替えで「ローカル」を選ぶと、自分のパソコンの ComfyUI で、Workflow Studio に保存したワークフローを使って画像を作れます。Nanobanana と同じ画面（プロンプト、参照画像、結果、「コマに挿入」）で使えるのが特徴です。Gemini の API キーは要りません。

> **注意**
> ローカルモードには、Workflow Studio（この機能に対応した版）と、画像を作れるワークフローの用意が必要です。ワークフローの作り方や、モデルの入れ方は、本書では扱いません。

### ワークフローを登録する

1. 「Nanobanana+」タブの上で「ローカル」を選びます。
2. 横に出た「⚙」（歯車のボタン）を押します。
3. 「表示名」（例：Flux.3 Klein）と、Workflow Studio に保存してあるワークフローを選び、「追加」を押します。複数登録できます。
4. 「閉じる」を押し、ドロップダウンで使いたいワークフローを選びます。

登録できるのは、画像を入れる LoadImage ノードを持つ Image Edit 系のワークフローです（例：Flux.3 Image Klein、Qwen Image 2.1）。登録した内容は、ブラウザに保存されます。

### 使い方

1. 左に Positive Prompt を書きます。
2. 右の「Image-to-Image」に、参照画像（元にする画像）を入れます。ローカルモードでは、**ワークフローが使える枚数まで**入れられます（上限は「Image-to-Image」の見出しの「(枚数/上限)」で確かめられます）。
3. 「画像を生成」を押します。結果は Nanobanana と同じ `ComfyUI/output/cc_nanobanana/` に保存され、「コマに挿入」で使えます。

参照画像は、ワークフローの画像入力に1枚目から順に入ります。

| ワークフロー | 入れられる画像 |
| --- | --- |
| Qwen Image 2.1（画像入力が最大10個） | 最大10枚。入れた枚数に合わせて、自動で入力が増減します（画像を1枚だけ入れて「差し替え」のように使うこともできます） |
| ワークフローの画像入力が固定の数のもの（Flux.3 Image Klein など） | その数まで。超えた分は使われず、警告が出ます |

> **ポイント**
> 登録したワークフローが「Qwen2.1（2枚）」のように画像入力が2個でも、Qwen Image 2.1 のワークフローなら、3枚目以降も使われます。

### 基本設定とシード

| 項目 | 内容 |
| --- | --- |
| 生成枚数 | 一度に作る枚数。複数のときはシードが1枚ごとに +1 される |
| 画像サイズ | ワークフロー既定／プリセット／カスタム |
| Steps・CFG・サンプラー・スケジューラ・Denoise | 「既定」や空欄のままなら、ワークフローの値がそのまま使われる |
| シード | ランダム／固定／生成ごとに+1（MOSS-Image タブと同じ）。「直前のシード」と「このシードを固定」で、気に入った結果を再現できる |

> **注意**
> ワークフローによっては、画像サイズなどが効かないことがあります。たとえば Flux.3 Image Klein は、出力サイズが入力画像に合わせて決まります。プロンプトと画像、Steps、CFG、シードは効きます。

「Nanobanana」モードでは、モデル・解像度・API キー・履歴などが見え、ローカルモードでは隠れます（シードはローカルモードだけに出ます）。

## 10-8 OCR タブで画像の文字と位置を読み取る

「OCR」タブは、画像に写っている文字を読み取り、その位置（枠）と一緒に一覧にする機能です。マンガのページだけでなく、雑誌の表紙やポスターも読めます。読み取った結果は、MOSS-Image タブのレイアウトとして送ったり、レイアウトタブや Image タブに文字として入れたりできます。

文字や枠の検出には、Ollama（ローカルの AI）のモデルを使います。クラウドの API キーは要りません。

### 必要なもの

- Ollama が動いていること（接続先は、画面の「URL」で指定します。既定は自分のパソコンです）
- 文字を読むモデル。次のように導入します（モデル名は、画面の「OCRモデル」で選びます）。

  ```
  ollama pull maternion/LightOnOCR-3:4b
  ```

- 「レイアウト検出」に使う画像対応のモデル（既定は `gemma4:e4b`）。コマ・キャラ・フキダシなどの枠を取るときに使います。
- 縦書きや装飾文字をより正確に読みたいときは、読み直し用のモデル（任意。下の「読み直し」）。

タブの上に、状態が「OCR: 利用可能」「OCR: OCRモデルが見つかりません」「OCR: Ollamaに接続できません」のどれかで表示されます。モデルを入れた直後は「モデル一覧を再読込」を押してください。

### 画面の構成

| 場所 | 内容 |
| --- | --- |
| 左 | 読み取る画像と、検出された枠。ここへ画像をドロップ（または貼り付け Ctrl＋V）する |
| 右上 | 「モード」と各種の設定（モデル、読み直し、判定、全体読み、全体プロンプト、検出するクラス） |
| 右下 | 「検出を実行」と、検出結果の一覧、コピーや MOSS-Image への送信 |

### はじめての読み取り

1. 左の枠に画像をドロップします（「画像を開く」でも選べます）。
2. 右の「モード」で、画像に合うものを選びます（迷ったら「自動（おすすめ）」）。
3. 「検出を実行」を押します。しばらくすると、画像の上に枠が表示され、右の「検出結果」に文字の一覧が出ます。
4. 間違った文字は、一覧の文字欄を直接書き換えます。枠は、ドラッグで移動、角で拡大・縮小できます。

> **注意**
> 最初に使うモデルは、読み込みに時間がかかります。モデルの切り替えでは、GPU のメモリ（VRAM）が足りなくなることもあります。「設定」タブの「VRAM調整（Ollama）」（第13章）が有効なら、検出の前に Ollama のほかのモデルを片付けます。

### モード

右上の「モード」を選ぶと、下の個別の設定がまとめて切り替わります。個別の設定を手で変えると、自動で「カスタム」になります。

| モード | 向いている画像 | 内容 |
| --- | --- | --- |
| 自動（おすすめ） | どれか迷うとき | 縦横比が極端なら縦長、それ以外は AI が画像を見て選ぶ。判定できないときは「マンガページ」。実験的な機能 |
| マンガページ | コマ割りのあるマンガ | 文字の検出に加えて、コマ・キャラ・フキダシなどの枠も検出する。読み直し・種類判定・全体プロンプトも行う |
| 雑誌表紙・ポスター | 色つきの背景に大小の文字が詰まった画像 | 文字の検出のみ。失敗したときは、白黒（グレースケール）で自動でやり直す。全体読みと全体プロンプトも行う |
| 文字のみ（文書・看板） | 文字が主役の画像 | 文字の検出だけを行う、いちばん速い設定。全体読みも行う |
| イラスト（文字なし） | 文字のない絵・写真 | 文字は読まず、コマ・キャラ・顔・物体の枠と全体プロンプトを作る |
| 縦長ページ（分割して読む） | 縦に長いページ（Webtoon など） | 縦に分割して読み、位置を元に戻してまとめる |
| カスタム | 自分で細かく決めたいとき | 個別の設定をそのまま使う |

### 検出する内容と枠の種類

枠には種類（クラス）があります。一覧の左の選択欄で、あとから変えられます。

| 種類 | 内容 |
| --- | --- |
| text | 読み取った文字そのもの。OCR モデルが検出する |
| balloon／sfx／caption | フキダシ・擬音・キャプション（文字を入れる枠）。レイアウト検出（別の AI）が取る |
| panel／character／face／object | コマ・キャラ・顔・物体（絵の枠）。レイアウト検出が取る |

「検出するクラス」のチェックで、レイアウト検出で探すものを選びます（文字は OCR のため常に検出されます）。

### 精度を上げる設定

| 設定 | 内容 |
| --- | --- |
| 文字枠を切り抜いて別モデルで読み直す | 検出した文字枠を1つずつ切り抜き、別のモデルで読み直す。縦書きや装飾文字に強い。枠の数だけ時間が掛かる。読み直し用には `ollama pull hf.co/LunarOilRig/PaddleOCR-VL-manga-GGUF:Q4_K_M`（マンガ特化の PaddleOCR-VL）が向いている |
| 選択枠を読み直す | 選んでいる枠だけを読み直す（ツールバーのボタン） |
| 検出後に切り抜きを意思決定モデルで判定する（任意） | 画像対応の判定用モデルで、文字枠の種類（フキダシ・キャプション・擬音・文字）を判定し、文字のない枠を除く。時間が掛かるので、必要なときだけ使う |
| OCRの前処理 | 雑誌表紙など密な画像で、OCR が空や同じ語の繰り返しになったときは、自動でグレースケールにして1回やり直す |
| 全体読み（Chat TE / ComfyUI） | 次の項で説明する |
| 全体プロンプト | 画像全体を英語で2〜3文に説明する。ONのときは、MOSS-Image へ送ると、プロンプトがこの文章に置き換わる。手で直せる |

### 全体読み（Chat TE）で縦書きを正確に読む

雑誌の表紙のように縦書きの大きな見出しが多い画像では、OCR モデルが読めないことがあります。そのとき便利なのが「全体読み（Chat TE / ComfyUI）」です。

ComfyUI のカスタムノード「Chat TE」（[comfyui-chat-te](https://github.com/ketle-man/comfyui-chat-te)）を使って、画像全体の文字を AI（Qwen3-VL）に1回で読ませます。実際に雑誌の表紙4枚で試したところ、縦書きの文字は、OCR モデルより全体読みのほうが多く読めました。ただし、全体読みは**文字だけで位置は出せません**。そこで、OCR の枠に読んだ文字を突き合わせて、枠の文字だけを置き換えます。どの枠にも合わなかった行は、この欄に残ります。

1. Chat TE を ComfyUI に入れておきます（導入方法は Chat TE の説明を見てください）。
2. 「全体読み（Chat TE / ComfyUI）」の欄の「URL」に、ComfyUI のアドレスが入っていることを確かめます（既定は、いま開いている ComfyUI です）。
3. 「モデル」で、Qwen3-VL-8B（なければ 4B）のテキストエンコーダを選びます。
4. 「画像全体をChat TEで読み、枠の文字を置き換える」にチェックを入れて、「検出を実行」を押します。モデルは、必要なら自動で読み込まれます。

「全体読みだけ実行」を押すと、検出済みの画像で全体読みだけを行えます。読んだ文字が下の欄に出ます（枠が無いときは、すべての行がそのまま残ります）。

> **ポイント**
> 「雑誌表紙・ポスター」と「文字のみ」のモードでは、このチェックが自動でオンになります（Chat TE のモデルが見つからないときはオフ）。

> **注意**
> 全体読みでは、ComfyUI 側で大きなモデルを読み込みます。Ollama のモデルが GPU のメモリに残っていると、読み込みに失敗することがあります。「VRAM調整（Ollama）」をオンにしておくと安心です。

### 結果の使い方

| ボタン | 動き |
| --- | --- |
| 全文をコピー | 読み取った文字を、読み順（上から下、右から左）でコピーする |
| JSONをコピー | 枠の位置・種類・文字を JSON でコピーする |
| MOSS-Imageタブへ送る | 検出結果を、物体・コマ・キャラ・文字の枠として MOSS-Image のレイアウトに入れる（10-6）。前回の OCR からの取り込み分は入れ替わる。「フキダシ/擬音/キャプションの枠に文字をまとめる」のチェックで、枠の中の文字を1つにまとめるかを選ぶ |

レイアウトタブの「テキスト」ツールや、Image タブのテキストツールの「Insert」を押すと、「テキストを挿入」の画面が開きます。挿入元に「OCR（OCRタブで検出したテキスト）」を選ぶと、検出した文字を、枠の位置に文字として入れられます（第7章・第9章）。

> **ポイント**
> 読み取った文字や枠は、画像ごとの一時的な結果です。MOSS-Image へ送る、コピーする、文字として入れるなど、使いたい用途を済ませてから、次の画像へ進んでください。

> **この章のまとめ**
> - Nanobanana（Nanobanana+ タブの「Nanobanana」モード）は Google の Gemini API で生成。`.env` に `NANOBANANA_API_KEY` を書いて ComfyUI を再起動する
> - Nanobanana で2枚以上作ると、サムネイルから選んだ画像が「コマに挿入」で入る。すべての画像は `output/cc_nanobanana` にも残る
> - 右の「Image-to-Image」に参照画像を入れると、キャラクターの見た目をそろえやすい
> - Workflow Studio があれば、レイアウトタブの「Generate」でコマごとに生成できる。元の画像は下に残る
> - Image タブの Inpaint・Outpaint で、部分修正や描き足しができる
> - 設定タブの「Nanobanana 設定」で、Gemini API とネイティブノード（`COMFY_API_KEY`）を切り替えられる
> - MOSS-Image タブは、物体・キャラ・文字の枠で位置を指定して、ページ全体を自分のパソコンで生成する。ページのコマとフキダシ・セリフは取り込める
> - レイアウトの「新規作成」は全部の枠を消し、「取り込み全クリア」は取り込んだ枠だけを消す。重なりは「最前面」「最背面」でも変えられる
> - Nanobanana+ の「ローカル」モードでは、Workflow Studio のワークフローで生成できる。Qwen Image 2.1 は、入れた画像の枚数（最大10枚）に合わせて入力が増減する
> - OCR タブは、画像の文字と位置を Ollama のモデルで読み取る。縦書きの多い表紙は「全体読み（Chat TE）」で文字を置き換えると読みやすい。結果は MOSS-Image へ送ったり、文字として入れたりできる
